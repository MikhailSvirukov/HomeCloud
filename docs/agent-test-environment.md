# Роль рабочей области: тестовая среда

## Назначение

Эта рабочая область отвечает за Rust test harness, изолированные component tests, моки и fake-реализации, Docker-интеграционные сценарии и fault/recovery-тесты. Нормативные требования находятся в [общем дизайне и межобластных требованиях](specification-v1.md) и в [SRS тестовой среды](specification-v1/test-environment.md). SRS — единственный источник требований к функциям, качеству, ограничениям и критериям проверки.

## Границы ответственности

Работай только в `test-environment/`, кроме явно назначенных общих файлов. Для моков и тестовой интеграции разрешено читать только публичные Rust traits/types и публичные Kotlin API/protocol interfaces; не читай приватную реализацию других областей. Если необходимого интерфейса нет, запроси его публикацию у владельца области.

## Правило постановки и выполнения задач

Каждая задача тестирования должна ссылаться на точные ID и редакции проверяемых требований SRS, включая `TST` требования. Не выводи ожидаемое поведение из issue, исходников чужой области или ежедневной заметки. Если для проверки не хватает формального требования или публичного контракта, сначала подготовь изменение SRS либо запрос владельцу контракта; тест, задающий новое поведение без такого основания, не добавляй.
