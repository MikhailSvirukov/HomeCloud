# Задание агенту: Android-клиент

См. общую спецификацию в [specification-v1.md](specification-v1.md). Реализовать только v1: автоматическое резервное копирование доступных фото и видео на сервер. Целевой стек из исходной идеи — Kotlin и Jetpack Compose; версию Android и механизм фоновой работы нужно зафиксировать перед реализацией.

## Требования

- При первом запуске запросить только необходимые разрешения Android на фото/видео; не запрашивать аудио, контакты, геолокацию и несвязанные права.
- Обнаружить существующие фото/видео и далее автоматически находить новые и изменённые элементы медиатеки.
- Изменённое содержимое отправлять как новую версию. Сохранять стабильный `upload_id` версии между повторами.
- Передачу разрешать по Wi-Fi и мобильной сети; при недоступности кластера сохранять очередь и повторять согласно настройкам.
- При каждом подключении запросить у выделенного сервера актуальные адреса, метки и ключи узлов, проверив подпись/закреплённый ключ.
- Перебирать storage-узлы с конфигурируемым per-node timeout. Использовать один и тот же `upload_id` при смене узла и повторах.
- Для каждого запроса к узлу включать login/password в зашифрованное сообщение. Не создавать долгоживущую авторизованную сессию.
- Сгенерировать и безопасно хранить ключевую пару клиента для расшифровки ответов. Передать открытый ключ при регистрации внутри зашифрованного запроса.
- Подписывать каждое клиентское сообщение своим signing key; пароль остаётся способом проверки учётной записи. Проверять подписи ответов серверов и узлов.
- Сжимать файл до шифрования; использовать согласованную гибридную криптосхему. Не хранить plaintext-файлы в промежуточной очереди без необходимости.
- Считать файл загруженным только после подтверждения кворумной записи и commit метаданных.
- Разбивать сжатое содержимое на ограниченные блоки/кадры для TCP-передачи в рамках одной логической загрузки. При обрыве начинать передачу заново с тем же `upload_id`; не реализовывать resume по блоку/смещению в v1.
- Локальное удаление файла не должно отправлять серверу команду удаления.

## Критерии приёмки

- Первичная загрузка старой медиатеки и автоматическая загрузка новых фото/видео работают в фоне в пределах ограничений Android.
- В очередь не попадают аудиофайлы.
- Таймаут одного узла приводит к попытке следующего; повтор подтверждённой/неподтверждённой операции не создаёт дубль.
- Ошибка/смена закреплённого ключа прекращает передачу и отображается как ошибка доверия, без автоматического принятия нового ключа.
- В сетевых логах приложения нет паролей, имён файлов или содержимого payload в открытом виде.

## Не реализовывать

Скачивание/просмотр/восстановление, возобновление чанков, управление версиями, удаление серверных копий, автоматическую ротацию ключей.
