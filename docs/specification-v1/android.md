# HomeCloud v1 — требования: Android-приложение

| Атрибут | Значение |
|---|---|
| Тип документа | Спецификация требований к программному обеспечению (SRS) для области |
| Версия | 1.0-draft |
| Статус | Проект; базовая линия v1 не утверждена целиком |
| Область | Мобильный клиент Android; локальная медиатека, разрешения, очередь, каталог и отправка медиа. |
| Общий дизайн | [specification-v1.md](../specification-v1.md) |

## 1. Назначение и границы области

Документ задаёт требования рабочей области «Android-приложение». Общая архитектура, модель доверия, сквозной протокол и открытые решения определены в [общем дизайне](../specification-v1.md). Требования с несколькими ответственными областями хранятся только в общем дизайне, чтобы исключить рассинхронизацию копий.

## 2. Требования области

Каждая строка задаёт отдельное проверяемое обязательство. `MUST / Утверждено` отражает согласие с требованием в диалоге, но весь документ остаётся draft до утверждения базовой линии.

### 5.1 Обоснование значений конфигурации клиента (`OPEN-017`)

Общий дизайн оставляет численные значения конфигурационных пределов открытыми. Для двух клиентских параметров этой области значения зафиксированы в требованиях `CFG-CL-019 / 2` и `CFG-AND-002 / 2`; здесь приведено только обоснование, чтобы не дублировать нормативный текст.

- `CFG-CL-019` — уровень 3 является штатным уровнем Zstandard: он даёт заметное сжатие при скорости, приемлемой для мобильного устройства. Диапазон `1..19` охватывает обычные (не «ультра») уровни Zstandard; уровни выше 19 относятся к режиму с высокой стоимостью сжатия и в клиенте не используются.
- `CFG-CL-017`, `CFG-CL-008`, `CFG-CL-018` — таймаут операции 30 с, пять bootstrap-попыток и интервал 1 с между ними: значения подходят для мобильной сети, не делают ожидание бесконечным и не создают нагрузку на сервер при недоступности; диапазоны отсекают нулевые и чрезмерные значения.
- `CFG-AND-002` — 10 000 версий покрывают крупную личную медиатеку, не позволяя файлу очереди расти безгранично. Верхняя граница 1 000 000 страхует хранилище устройства, нижняя 1 допускает тестовые конфигурации. Предел измеряется числом версий; заполнение очереди не удаляет и не заменяет уже принятые элементы.

Эти решения не задают серверные пределы и не закрывают `OPEN-017` для остальных параметров; изменение значений — изменение SRS.

## 6. Приёмка

Каждое требование проверяется методом, указанным в соответствующей таблице. Межобластные проверки используют тестовые контракты и сценарии, определённые общим дизайном и спецификацией тестовой среды.
