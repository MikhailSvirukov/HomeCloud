# HomeCloud v1 — требования: Тестовая среда

| Атрибут | Значение |
|---|---|
| Тип документа | Спецификация требований к программному обеспечению (SRS) для области |
| Версия | 1.0-draft |
| Статус | Проект; базовая линия v1 не утверждена целиком |

## 1. Назначение и границы области

Документ задаёт требования рабочей области «Тестовая среда». Общая архитектура, модель доверия, сквозной протокол и открытые решения определены в [общем дизайне](../specification-v1.md). Требования с несколькими ответственными областями хранятся только в общем дизайне, чтобы исключить рассинхронизацию копий.

## 2. Требования области

Каждая строка задаёт отдельное проверяемое обязательство. `MUST / Утверждено` отражает согласие с требованием в диалоге, но весь документ остаётся draft до утверждения базовой линии.

### TST: инфраструктура и fault injection

|---|---|---|---|---|---|
| `TST-001 / 1` | Тестовая среда должна запускать выделенный сервер и storage-узлы в Docker-контейнерах. | MUST / Утверждено | Test environment | Интеграционный тест запуска стенда | D |
| `TST-002 / 1` | Тестовая среда должна создавать изолированную Docker-сеть для компонентов тестового кластера. | MUST / Утверждено | Test environment | Инспекция созданной сети | D |
| `TST-003 / 1` | Управляющий тестовый harness должен быть написан на Rust. | MUST / Утверждено | Test environment | Инспекция workspace и исходников | D |

| `TST-005 / 2` | Тестовая среда должна поддерживать аварийное принудительное отключение контейнера storage-узла без штатного завершения процесса приложения. | MUST / Утверждено | Test environment | Fault-injection тест немедленного прекращения процесса и последующего перезапуска контейнера | D |
| `TST-006 / 2` | Тестовая среда должна поддерживать выборочное программное ограничение сетевой связности между узлами. | `TST-016 / 1` | Тестовая среда должна поддерживать аварийное завершение процесса storage-узла при работающем контейнере. | MUST / Утверждено | Test environment | Fault-injection тест остановки процесса с последующим запуском в прежнем контейнере | D |
| `TST-017 / 1` | Тестовая среда должна сохранять данные Docker volume storage-узла между остановкой и повторным созданием контейнера. | MUST / Утверждено | Test environment | Тест рестарта контейнера с проверкой сохранности тома | D |
| `TST-008 / 1` | Тестовая среда должна запускать интеграционные проверки компонентов в Docker. | MUST / Утверждено | Test environment | Интеграционный запуск заданного сценария | D |
| `TST-009 / 2` | Новый интеграционный или recovery-сценарий должен добавляться как отдельная реализация публичного интерфейса сценария без изменения кода общего запуска контейнеров и сети harness. | MUST / Утверждено | Test environment | Контрольный тестовый pull request добавляет и запускает новый сценарий изменением только нового модуля сценария и его регистрации | D |
| `TST-010 / 2` | Тестовая среда должна проверять, что storage-узлы не подтверждают запись blob при недоступности большинства узлов. | MUST / Утверждено | Test environment | Fault-injection тест потери blob-кворума | D |
| `TST-013 / 1` | Тестовая среда должна проверять, что storage-узлы не подтверждают commit метаданных при недоступности большинства Raft-узлов. | MUST / Утверждено | Test environment | Fault-injection тест потери Raft-кворума | D |
| `TST-042 / 1` | Тестовая среда должна проверять, что узел засчитывается в blob-кворум только после успешной фиксации blob в стабильном хранилище и что подтверждённый blob доступен после аварийного отключения и перезапуска узла. | MUST / Утверждено | Test environment / distributed | Crash-тест после подтверждения локальной долговременной записи с проверкой полного содержимого и SHA-256 blob после перезапуска | D |

- [`OPEN-022`](../specification-v1.md#реестр-открытых-решений) — численные цели производительности устанавливаются после прототипа и воспроизводимых замеров; требования к сбору измерений заданы в `TST-058`.


## 5. Приёмка

Каждое требование проверяется методом, указанным в соответствующей таблице. Межобластные проверки используют тестовые контракты и сценарии, определённые общим дизайном и спецификацией тестовой среды.
