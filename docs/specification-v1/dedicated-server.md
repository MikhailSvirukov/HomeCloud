# HomeCloud v1 — требования: Выделенный сервер

| Атрибут | Значение |
|---|---|
| Тип документа | Спецификация требований к программному обеспечению (SRS) для области |
| Версия | 1.0-draft |
| Статус | Проект; базовая линия v1 не утверждена целиком |
| Область | Регистрация аккаунтов и установок, bootstrap доверия, топология, межузловое распространение данных, heartbeat и кластерное время. |
| Общий дизайн | [specification-v1.md](../specification-v1.md) |

## 1. Назначение и границы области

Документ задаёт требования рабочей области «Выделенный сервер». Общая архитектура, модель доверия, сквозной протокол и открытые решения определены в [общем дизайне](../specification-v1.md). Требования с несколькими ответственными областями хранятся только в общем дизайне, чтобы исключить рассинхронизацию копий.

### FR-TIME
| ID / рев. | Требование | Приоритет / статус | Ответственный | Метод и критерий проверки | Источник |
|---|---|---|---|---|---|
| `FR-TIME-001 / 1` | Выделенный сервер должен использовать системные часы своего хоста как источник кластерного wall-clock времени. | MUST / Утверждено | Dedicated server | Инспекция конфигурации времени | D |
| `FR-TIME-004 / 1` | Выделенный сервер должен фиксировать время получения heartbeat-ответа. | MUST / Утверждено | Dedicated server | Тест временных меток | D |
| `FR-TIME-005 / 3` | По завершении heartbeat-обмена с временными метками `t1` (отправка запроса выделенным сервером), `t2` (получение запроса storage-узлом), `t3` (отправка ответа storage-узлом) и `t4` (получение ответа выделенным сервером) выделенный сервер должен вычислять смещение `offset_ms = ((t2 - t1) + (t3 - t4)) / 2`, где положительное значение означает, что часы storage-узла опережают часы выделенного сервера; деление целого результата на два выполняется с округлением к нулю. | MUST / Утверждено | Dedicated server | Проверка вычисления знака, значения и округления offset на наборах фиксированных временных меток | D |
| `FR-TIME-014 / 2` | По тем же временным меткам выделенный сервер должен вычислять сетевую задержку round-trip как `rtt_ms = (t4 - t1) - (t3 - t2)`. Оценка offset должна исходить из предположения о симметричной сетевой задержке; фактическую асимметрию обмен не определяет, а её возможная абсолютная погрешность ограничена `rtt_ms / 2`. Если вычисленный `rtt_ms` отрицателен, выделенный сервер должен отбросить образец и не обновлять оценку offset по нему. | MUST / Утверждено | Dedicated server | Проверка RTT и указанной оценки погрешности на фиксированных временных метках с симметричными и асимметричными задержками, тест отрицательного RTT | D |
| `FR-TIME-006 / 2` | В следующем heartbeat-запросе выделенный сервер должен передавать storage-узлу оценку offset, рассчитанную по последнему допустимому обмену; если допустимого образца ещё нет, поле offset должно быть `null`. | MUST / Утверждено | Dedicated server | Интеграционный тест передачи последней допустимой оценки после корректного и некорректного образцов, а также начального `null` | D |

## 5. Приёмка

Каждое требование проверяется методом, указанным в соответствующей таблице. Межобластные проверки используют тестовые контракты и сценарии, определённые общим дизайном и спецификацией тестовой среды.
