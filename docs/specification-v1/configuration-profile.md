# HomeCloud v1 — профиль конфигурации

Нормативное приложение общего SRS. Владелец — dedicated-server; настройки применяет соответствующая область. Это диапазоны корректной конфигурации, а не обещание производительности; численные цели остаются в OPEN-022. Источник новых решений — `T`.

Для CFG-CL-001–005, 013, 021, 033–036, 038–040, 048, CFG-OBS-001/004 действуют структурные требования исходного SRS: обязательные идентичности, пути, состав и ключи не получают вымышленных defaults. Оператор задаёт манифест, корень данных, пути секретов, путь журнала и TLS-материалы для нелокальных метрик. CFG-AND-001 определяет targetSdk при выпуске и не является runtime-параметром. Период WorkManager не ниже 15 минут по существующим Android-требованиям.

Обоснование: таймауты ограничивают ожидание; предел заголовка ограничивает служебные аллокации независимо от размера файла. Лимит файла и память обязательны для настройки оператором, поскольку v1 держит полную сжатую версию в цепочке RAM-буферов. Изменение значения в допустимом диапазоне не меняет версию протокола; изменение опубликованного default или диапазона требует ревизии SRS.

## 3. Взаимные ограничения

Каждая строка — отдельное проверяемое условие CFG-CL-051.

| Настройки | Условие корректности |
|---|---|
| CFG-CL-029 | minimum ≤ maximum отдельно для login и password |
| CFG-CL-006/014 | heartbeat response timeout < heartbeat interval |
| CFG-CL-042/043 | attempt deadline ≤ total deadline; retry interval не продлевает общий deadline |
| CFG-CL-011/046 | Максимальный логический заголовок вместе с максимально допустимым внешним заголовком, подписью, HPKE encapsulated key и AEAD tag помещается в frame body |
| CFG-CL-046/029/031/032/047 | Весь ответ топологии фиксированного состава, каждая максимальная единичная запись и каждый служебный запрос помещаются в логический заголовок |
| FR-CAT-011, CFG-CL-011/046 | Число entries — верхняя граница: сервер завершает страницу раньше по байтовому пределу; каждая допустимая одиночная запись помещается, иначе конфигурация отклоняется |
| CFG-CL-012 | Список размеров блоков непустой, строго возрастает; размеры кратны 4096; общая ёмкость не меньше максимального блока; перераспределение ёмкости пулов не выходит за общий предел |
| CFG-CL-020/012/026 | На одну активную payload-операцию предусмотрено не менее 2 × B(max_file_size) + 2 × largest_block байтов для полной сжатой и распакованной цепочек с округлением; произведение на active payload operations не превышает общую payload-ёмкость; B(n) определена в protocol-details.md §2 |
| CFG-CL-010/030/047 | Генерируемый PHC помещается в verifier limit; m ≥ 8 × p; параметры сохранённого PHC находятся в поддерживаемых диапазонах таблицы до проверки пароля; используются параметры записи, а не текущие defaults |
| CFG-CL-013 | Серверы согласуют wire-ограничения, статический состав и поддерживаемый PHC-профиль; Android использует совместимые пределы файлов, кадров, заголовков, логина, пароля, метки и имени |
| CFG-OBS-002 | rotation age ≤ retention; maximum single file ≤ maximum total logs |
| CFG-OBS-003/004 | Metrics port отличается от прикладного порта на том же адресе; для нелокальной привязки обязательны TLS-материалы |

Бюджет payload не включает память runtime, заголовков, очередей, OpenRaft, Argon2id и ОС: оператор оставляет отдельный запас. Формула ёмкости предотвращает взаимное ожидание двух полных цепочек; она не является обещанием пропускной способности.
