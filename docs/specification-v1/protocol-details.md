# HomeCloud v1 — уточнения общего протокола

Нормативное приложение общего SRS. Владелец — dedicated-server; потребители — четыре рабочие области. Источник `T` обозначает технические решения, делегированные заказчиком. Приложение использует согласованные TCP-фрейминг, HPKE, подписи и коды ошибок; оно не вводит новую рабочую область.

`uuid` — CBOR byte string из 16 байт; `key`, `hash`, `content_tag` — byte string из 32 байт. `read_index` и `commit_index` — uint64, `result_code` — uint32. Типы uint32/uint64/int64 обозначают диапазоны значений, а не фиксированную ширину CBOR. Общая межсерверная оболочка — `[message_type, args]`. Все позиции массива обязательны; отсутствие значения кодируется `null` только там, где это разрешено схемой.

## 2. Границы полей

Таблица нормативна для INT-NET-086. CBOR overhead учитывается в пределах закодированного заголовка и кадра. Фиксированные длины ключей, UUID, SHA-256 и токенов сохраняются.

| Поле | Тип и ограничение |
|---|---|
| login, password | CBOR text; длины CFG-CL-029; ASCII-набор логина FR-DED-027; пароль — UTF-8 без нормализации |
| source_name | UTF-8 text; CFG-CL-032 |
| label, responder_label | UTF-8 text; CFG-CL-031 |
| host | ASCII text, 2–45 байт; канонический IPv4/IPv6 по INT-NET-070; без скобок и zone identifier |
| original_size, compressed_size | uint64; каждый не более CFG-CL-020 |
| timestamp_ms | int64 Unix ms |
| nodes, replica_ids | Не более числа storage-узлов манифеста; ID не повторяются, порядок манифеста |
| entries | Не более размера страницы FR-CAT-011; ответ ограничен также CFG-CL-046 и CFG-CL-011; пустая промежуточная страница запрещена |
| verifier | ASCII text PHC Argon2id, не более CFG-CL-047; параметры и длины проходят проверку профиля конфигурации до вызова Argon2id |
| rpc_bytes | Byte string; вместе с оболочкой помещается в CFG-CL-046 и CFG-CL-011; дробление snapshot выполняет адаптер OpenRaft |
| payload_length | Положительный uint32 — число байтов после логического заголовка data-кадра; полный кадр помещается в CFG-CL-011 |
| transfer_compressed_size | uint64 в диапазоне 1..B(original_size); B(n) = n + floor(n / 256) + 64, вычисляется с проверкой переполнения |
| Прочие массивы и поля | Только точные схемы этого приложения и общего SRS; дополнительные поля запрещены |

## 3. Межсерверные сообщения

`metadata` — ровно `[source_name, timestamp_ms, original_size, compressed_size, sha256]` с типами §2. Метаданные описывают исходный upload; повторное сжатие для межсерверной передачи их не меняет. Отдельный transfer_compressed_size описывает текущий Zstandard-поток.

## 5. Идентичность повторной регистрации

Технический выбор — [HMAC по RFC 2104](https://www.rfc-editor.org/rfc/rfc2104) с SHA-256 и отдельным секретом dedicated. Argon2id остаётся механизмом проверки пароля. Незасекреченный быстрый хэш пароля для сравнения запросов не используется.

| ID / рев. | Требование | Приоритет / статус | Ответственный | Метод и критерий проверки | Источник |
|---|---|---|---|---|---|
| `INT-NET-109 / 1` | Dedicated должен вычислять content_tag = HMAC-SHA-256(K, deterministic_cbor(["homecloud.registration.v1", login, password, x25519_key, ed25519_key])) без нормализации строк. | MUST / Утверждено | Dedicated | Известный HMAC-вектор и изменение каждого поля; точный повтор сохраняет tag | T |
| `CFG-CL-048 / 1` | Секрет K должен состоять из 32 CSPRNG-байтов и храниться в отдельном постоянном файле dedicated по заданному оператором пути с ограничениями доступа CFG-CL-033; он не должен автоматически пересоздаваться при обычном старте или потере. | MUST / Утверждено | Dedicated | Генерация, права, restart и отказ при отсутствующем файле | T |
| `INT-NET-110 / 1` | Dedicated должен проверять пароль по account PHC и сравнивать content_tag с сохранённым результатом до возврата успешного replay регистрации. | MUST / Утверждено | Dedicated | Иной пароль или ключи не дают успешный replay; точный повтор возвращает прежний ID | T |
| `NFR-SEC-010 / 1` | Команды, snapshot и журналы не должны сохранять открытый пароль, вход HMAC или секрет K; storage может сохранять tag, PHC и согласованные публичные поля регистрации. | MUST / Утверждено | Dedicated / distributed | Инспекция схем хранения и контрольные значения в журнале/snapshot | T |
| `NFR-SEC-011 / 1` | Оператор должен сохранять K в резервной копии секретной конфигурации dedicated вместе с постоянными ключами; восстановленный dedicated должен использовать прежний K, а при отсутствующем или нечитаемом файле регистрация должна оставаться недоступной с диагностикой причины. | MUST / Утверждено | Dedicated | Восстановление исходного K сохраняет replay; потерянный K не генерируется автоматически | T |

Решение добавляет один секретный файл dedicated; ключи Android и клиентские аргументы регистрации сохраняются. Автоматическая замена и ротация K отнесены к следующим релизам.
