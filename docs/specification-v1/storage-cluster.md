# HomeCloud v1 — требования: Storage-кластер

| Атрибут | Значение |
|---|---|
| Тип документа | Спецификация требований к программному обеспечению (SRS) для области |
| Версия | 1.0-draft |
| Статус | Проект; базовая линия v1 не утверждена целиком |
| Область | TCP endpoint узла, аутентификация, каталог и blob-хранилище, репликация, Raft, восстановление и runtime узла. |
| Общий дизайн | [specification-v1.md](../specification-v1.md) |

## 1. Назначение и границы области

Документ задаёт требования рабочей области «Storage-кластер». Общая архитектура, модель доверия, сквозной протокол и открытые решения определены в [общем дизайне](../specification-v1.md). Требования с несколькими ответственными областями хранятся только в общем дизайне, чтобы исключить рассинхронизацию копий.

## 2. Требования области

Каждая строка задаёт отдельное проверяемое обязательство. `MUST / Утверждено` отражает согласие с требованием в диалоге, но весь документ остаётся draft до утверждения базовой линии.

| `FR-UP-015 / 1` | Storage-узел должен отменять незавершённую загрузку после конфигурируемого периода сетевого бездействия. | MUST / Утверждено | Storage-узлы | Тест silent disconnect с управляемым таймером | D |

| `FR-UP-024 / 1` | Если storage-узел не может завершить прямую запись из-за исчерпания места, он должен удалить неполный blob, не менять ранее committed-данные, не фиксировать метаданные и вернуть `0x0007_0002` согласно `INT-NET-064`. | MUST / Утверждено | Distributed server | Тест исчерпания места с проверкой partial-file cleanup, сохранности committed-версий и кода ошибки | D |
| `FR-UP-020 / 2` | Storage-узел должен возвращать определённый код для ошибок загрузки согласно `INT-NET-064`, включая отказ аутентификации, постоянную ошибку файла, недоступность Raft-кворума, недостигнутый кворум репликации blob, временную недоступность, исчерпание ёмкости и внутреннюю ошибку. | MUST / Утверждено | Storage-узлы | Протокольные тесты точного кода для каждого класса ошибки | D |

Решение `OPEN-007`: выбрана стабильная линия OpenRaft `0.9.25`; линия `0.10` остаётся alpha и для v1 не используется. Сериализация RPC — CBOR (RFC 8949) через `ciborium` над serde-представлением типов OpenRaft; альтернативы `bincode`/`postcard` отклонены как не-CBOR и менее пригодные для проверки на уровне протокола, protobuf — из-за отдельной схемы без выигрыша для непрозрачного `rpc_bytes`. Транспортный адаптер реализует `RaftNetwork`/`RaftNetworkFactory` OpenRaft 0.9 и передаёт каждый RPC как `message_type = 3` с `[rpc_bytes]` согласно `INT-NET-074 / 2`; принимающий узел передаёт байты локальному экземпляру OpenRaft (`FR-CL-031 / 1`). Клиент не перенаправляется к лидеру (`INT-NET-078 / 1`): координирующий узел передаёт команду текущему лидеру внутренним взаимодействием кластера.
