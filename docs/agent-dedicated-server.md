# Задание агенту: выделенный сервер

См. [общую спецификацию](specification-v1.md). В v1 это control-plane/bootstrap-сервис, не файловый proxy, не ретранслятор межузлового трафика и не полноценная админ-панель. Целевой серверный стек из исходной идеи — Rust.

## Требования

- Иметь закреплённую ключевую идентичность: отдельные пары для расшифровки входящих сообщений и подписи исходящих.
- Принимать клиентскую регистрацию по уникальному login и паролю; регистрационный запрос зашифрован на открытый ключ выделенного сервера.
- Привязать открытый ключ клиента для шифрования ответов к учётной записи. Пароль преобразовать в salted verifier, не сохранять plaintext.
- Распространить запись нового пользователя (login, verifier, открытый ключ клиента) по кластеру и подтвердить регистрацию после кластерного commit согласно политике консенсуса.
- На каждом новом подключении клиента вернуть актуальную статическую топологию: адреса, labels, encryption public keys и signing public keys.
- Ответ шифровать на публичный ключ клиента и подписывать собственным signing key. Label отправителя включать в зашифрованный логический header.
- Получать и хранить сведения о фиксированном составе кластера, сообщённые при первичном bootstrap узлов.
- Не принимать/хранить/проксировать фото и видео.
- Отправлять отдельные от Raft heartbeat-сообщения с настроенным интервалом; фиксировать несколько последовательных пропусков по настроенному порогу и timeout.
- Health-статус v1 не включать в топологию клиента и не распространять на storage-узлы.
- Для временной недоступности выдавать различимые ошибки, чтобы клиент применил настроенные число повторов и интервал.

## Будущие релизы

- Полноценная административная панель.
- Регистрация нового storage-узла и распространение изменённого состава/доступности кластера.
- Ротация ключей и восстановление доверия после смены ключа.
