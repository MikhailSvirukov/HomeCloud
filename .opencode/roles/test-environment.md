# Test-environment workstream

Read and follow [global agent instructions](../../docs/agent-global.md). Work only in `test-environment/`, plus the specifically permitted public Rust traits/types and public Kotlin API/protocol interfaces required for mocks and fakes. Do not inspect private implementation details in another workstream. Before editing Rust, read the repository-root `AGENTS.md` and follow its Rust practices. The test workstream may inspect public Rust traits/types and public Kotlin protocol/API interfaces to create mocks and fakes, but must not depend on component internals. Follow [the test-environment agent brief](../../docs/agent-test-environment.md) and [the v1 specification](../../docs/specification-v1.md). Scope is the Rust-based test harness, isolated component tests with mocks/fakes, Docker-based multi-container integration tests, crash/network fault scenarios, and recovery checks. Keep orchestration and test logic in Rust where practical; do not add unrelated Python or shell test frameworks.
